# 06. 로드맵

마일스톤은 날짜가 아니라 **통과 기준**으로 끝난다. 기준을 통과하지 못하면 다음으로 넘어가지 않는다.

크기는 상대값이다(M0 = 1). 1인 개발 기준으로 M0~M3(슬라이스 완성)만 해도 수개월, 출시까지는 에셋 제작량에 따라 1~3년 규모다.

## 개요

| 마일스톤 | 내용 | 크기 | 결과물 |
| --- | --- | --- | --- |
| **M0** | 위험 검증: 네트워크 뼈대 + 시뮬레이션 코어 | 1 | 회색 상자 프로토타입 2개 |
| **M1** | FPS 기반 | 1.5 | 2인이 적과 싸울 수 있다 |
| **M2** | 건축과 공장 | 2.5 | 2인이 자동화 라인을 짓고 저장한다 |
| **M3** | 루프 완성 = **버티컬 슬라이스** | 2 | 30분 플레이, 외부 테스트 |
| **M4** | Steam과 8인 | 2 | Steam 친구 초대로 최대 8인 플레이 |
| **M5** | 콘텐츠 확장 + PvP + 데모 | 4+ | Steam 데모 |
| **M6** | 정식 출시 준비 | 6+ | 출시 |

## M0 — 위험 검증

가장 비싼 실수 두 가지를 가장 먼저 확인한다. 그래픽은 전부 회색 상자다.

**진행 상황 (v0.1.0)**

| 할 일 | 상태 |
| --- | --- |
| Godot 프로젝트, 폴더 구조, 정적 타입 강제, 테스트 실행기, CI | 완료 |
| 콘텐츠 데이터와 검증(`ContentDB`), 슬라이스 데이터 입력 | 완료 |
| `sim/` 코어: 격자, 벨트, 채굴기·제련기·조립기, 분배/합류기, 저장소, 발전기, 전력망 | 완료 (단위 테스트 20개) |
| 직렬화 왕복과 결정론 테스트 | 완료 |
| 벤치마크 | 완료 — 결과는 아래 |
| 사격 감각 테스트 빌드(사격장) — M1에서 당겨 옴 | 첫 버전 완료, **사람의 평가 대기** |
| 네트워크 뼈대: ENet 호스트/참가, 이동 동기화, 설치 요청 → 검증 → 방송, 중도 참가 스냅샷 | **다음 작업** |
| 공장 상태 복제 프로토타입(클라이언트 시각 예측 + 2Hz 보정) | 네트워크 뼈대 다음 |

**벤치마크 결과** (GDScript, Godot 4.7.2 에디터 바이너리, 클라우드 4코어 VM)

| 규모 | 평균 틱 | 최악 틱 | 예산 2ms |
| --- | --- | --- | --- |
| 슬라이스: 설비 609개, 벨트 2,001칸 | 0.61ms | 3.3ms | 통과 |
| 출시 목표: 설비 6,090개, 벨트 20,010칸 | 10.8ms | 37.8ms | **5배 초과** |

판정: 슬라이스(M3)까지는 GDScript로 충분하다. 출시 규모는 GDScript로 불가능하므로 M5 진입 전에 틱 코어를 네이티브로 옮긴다([D-025](07_decisions.md)).

**통과 기준**

- [x] 테스트 "채굴기 1 + 분배기 + 제련기 2, 정상 상태에서 600틱 동안 주괴 +60개"가 통과
- [x] [05](05_vertical_slice.md) 수치 검산 표의 공장·전력 항목이 테스트로 통과
- [x] 벤치마크로 코어 언어를 결정했다
- [ ] 두 창에서 한쪽이 놓은 상자가 다른 쪽에 보이고, 늦게 들어온 쪽도 같은 세계를 본다
- [ ] 클라이언트 화면의 벨트 물건이 보정 때 눈에 띄게 튀지 않는다. 튀면 보간 방식으로 전환을 결정한다

## M1 — FPS 기반

**할 일**: 1인칭 컨트롤러(걷기·달리기·점프·앉기·슬라이딩), 무기 3종, 반동·조준·재장전, 명중 판정과 호스트 검증, 적 2종 AI, 체력·쓰러짐·부활, 플레이어별 전리품, 시험용 전투 맵.

컨트롤러와 무기 3종의 첫 버전은 사격장 테스트 빌드로 이미 들어가 있다([08](08_dev_process.md#테스트-빌드)). 사람이 해 보고 돌려준 조정값을 `data/weapons.json`에 반영하는 과정을 M1 내내 반복한다.

**통과 기준**

- [ ] 2인이 시험 맵에서 적 20마리를 처치하는 동안 동기화 오류가 없다
- [ ] 인위적 지연 150ms에서도 사격이 즉각 반응한다
- [ ] 테스트 빌드를 해 본 사람(개발자 본인 포함)이 "쏘는 게 재미있다"고 말한다. 아니면 M2로 가지 않고 여기서 다듬는다

## M2 — 건축과 공장

**할 일**: 건축 모드(미리보기, 격자/자유 배치, 회전, 벨트 드래그), 구조물 View, 벨트 MultiMesh 렌더링, 기계 패널 UI, 상태 아이콘, 인벤토리와 손 투입, 작업대 제작, 되돌리기·복사, 역할 권한, 저장/불러오기/자동 저장/백업, 밭과 작물.

**통과 기준**

- [ ] 2인이 [05](05_vertical_slice.md)의 기준 라인을 짓고, 저장하고, 재시작 후 그대로 돌아간다
- [ ] 저장 중 강제 종료 10회 후에도 불러올 수 있는 세이브가 항상 있다
- [ ] 방문자 역할은 설치·철거가 호스트에서 거절된다(클라이언트를 조작해도)
- [ ] 설비 500개 공장에서 60fps

## M3 — 루프 완성 (버티컬 슬라이스)

**할 일**: 실제 맵(정원 + 골짜기), 미니보스, 조립기, 비콘과 구역 복원 연출, 무기 개조, 시작 안내(짧은 목표 표시), 임시 에셋 정리, 사운드 최소 세트, 외부 플레이 테스트.

**통과 기준**: [05의 완료 기준](05_vertical_slice.md#완료-기준) 전체.

**여기가 갈림길이다.** 재미 기준을 통과하면 M4로. 통과하지 못하면 무엇이 문제인지에 따라 슬라이스를 고치거나 범위를 줄인다([07](07_decisions.md)의 대비책 참고).

## M4 — Steam과 8인

**할 일**: Steamworks 등록, GodotSteam 통합, 로비·초대·참가, 4인 → 8인 순서로 부하 테스트, 연결 끊김 처리, 3~8인 적 보정, 설정 메뉴(그래픽·키·음량), Steam Deck 확인.

**통과 기준**

- [ ] 서로 다른 네트워크의 4명이 Steam 초대만으로 접속한다
- [ ] 8인 접속 상태에서 호스트가 60fps와 업로드 예산을 지킨다(사람이 모자라면 자동 조작 클라이언트로 채워 측정)
- [ ] 4인 1시간 플레이에서 진행 불가 버그가 없다
- [ ] 누가 어떤 식으로 나가도 호스트 월드가 손상되지 않는다

## M5 — 확장과 데모

우선순위 순서. 위에서부터 하고, 데모 일정에 맞춰 자른다.

1. 구역 2~3개, 구역별 적 1~2종과 보스
2. 설비 확장: 태양광, 풍력, 축전지, 자동 수확기, 온실, 상위 벨트
3. 연구/설계도 해금 구조
4. 건축 확장: 조각 종류, 색상, 청사진
5. 작물·장식·가구 확장, 동물 등장
6. 특수 장비(씨앗 발사기, 전자기 무기)
7. **PvP 전술 아레나**: 경기 진행(라운드·공수 교대·승패), 씨앗 심기, 라운드 자금과 구매, 연막·섬광, 전용 맵 1개. 사격 규칙은 사격장 테스트 빌드에서 미리 조정해 둔다
8. 아트·사운드 교체, 스토어 페이지, 데모 빌드

## M6 — 출시 준비

현지화(한국어·영어 우선), 업적, 최적화, 접근성 옵션, 외부 테스트, 얼리 액세스 여부 결정.
