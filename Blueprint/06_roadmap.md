# 06. 로드맵

마일스톤은 날짜가 아니라 **통과 기준**으로 끝난다. 기준을 통과하지 못하면 다음으로 넘어가지 않는다.

크기는 상대값이다(M0 = 1). 1인 개발 기준으로 M0~M3(슬라이스 완성)만 해도 수개월, 출시까지는 에셋 제작량에 따라 1~3년 규모다.

| **M2** | 건축과 공장 | 2.5 | 2인이 자동화 라인을 짓고 저장한다 — **완료 (사람의 플레이 확인 남음)** |

**통과 기준**

- [x] 테스트 "채굴기 1 + 분배기 + 제련기 2, 정상 상태에서 600틱 동안 주괴 +60개"가 통과
- [x] [05](05_vertical_slice.md) 수치 검산 표의 공장·전력 항목이 테스트로 통과
- [x] 벤치마크로 코어 언어를 결정했다
- [x] 한쪽이 놓은 구조물이 다른 쪽에도 생기고, 늦게 들어온 쪽도 같은 세계를 갖는다 — 4개 프로세스의 상태 해시 일치로 확인
- [x] 클라이언트의 벨트 물건이 보정으로 튀지 않는다 — 보정 자체가 없는 방식으로 확정

남은 확인: 위 두 항목은 화면 없는 자동 점검으로 통과한 것이다. 실제 PC 두 대(또는 창 두 개)에서 사람이 눈으로 본 적은 아직 없다. M1 첫 플레이 때 함께 확인한다.

**통과 기준**

- [x] 적과의 전투가 여러 명에게 일관되게 전달된다 — 4개 프로세스 점검: 적 생성·처치가 전원에게 보이고, 쓰러진 플레이어를 다른 플레이어가 일으킨다
- [x] 잘못된 사격 보고(너무 빠름, 탄환 수 초과, 모르는 무기)는 호스트가 거절한다
- [x] 파쿠르 세 동작이 자동 점검을 통과한다
- [ ] 사람이 해 봤을 때 적과 싸우는 것이 재미있다 — **아직 아무도 해 보지 않았다.** 적의 속도·체력·공격 간격, 벽 달리기 수치는 전부 첫 값이다
- [ ] 인위적 지연 150ms에서도 사격이 즉각 반응한다 — 구조상 사격 연출은 전부 내 화면에서 먼저 일어나지만, 지연을 넣고 측정하지는 않았다
- [ ] 2인이 실제로 적 20마리를 처치하는 동안 문제가 없다 — 사람 손으로는 아직

남은 두 항목은 사람이 직접 해 봐야 닫힌다. M2 중 아무 때나 두 창을 띄워 확인하면 된다.

알려진 한계:

- 적은 호스트의 지형과 호스트 플레이어의 몸에만 부딪힌다. 다른 플레이어는 호스트 쪽에서 위치값으로만 존재하므로, 적이 그 플레이어를 밀지는 못한다(공격 판정은 정상).
- 길찾기 메시는 전투 구역의 고정 지형만 포함한다. 플레이어가 지은 구조물은 길찾기에 반영되지 않는다(적은 건축 가능 구역에 오지 않으므로 지금은 문제가 아니다).
- 원거리형의 침은 호스트가 가진 위치 기준으로 맞는다. 지연이 큰 클라이언트는 "피했는데 맞았다"고 느낄 수 있다.

**통과 기준** ([05의 완료 기준](05_vertical_slice.md#완료-기준))

- [x] 흐름을 처음부터 끝까지 진행할 수 있다 — `--slicetest`가 손 채굴 → 캡슐 제작 → 골짜기 → 수호체 → 비콘 → 복원 → 저장을 한 번 돈다. 단, 기다림(작물 성장, 재료 모으기)은 지급으로 건너뛰고 수호체는 직접 피해로 쓰러뜨린다
- [x] 어느 시점에 저장하고 불러와도 상태가 같다
- [x] 혼자서도 끝까지 진행할 수 있다(구조상). 사람이 실제로 끝까지 해 보지는 않았다
- [ ] 2인이 처음부터 끝까지 — 사람 둘이 해 본 적이 없다
- [ ] 2인 30분 연속 플레이 5회 중 진행 불가 버그 0회
- [ ] 설명 없이 10분 안에 첫 주괴 자동 생산
- [ ] 과반이 "더 하고 싶다"
- [ ] 30분에 맞는가 — **재 보지 않았다.** 수치는 05의 계산값이고, 실제 소요 시간은 사람이 해 봐야 안다

아래 네 줄이 M3의 진짜 목적이다. 통과하지 못하면 콘텐츠를 늘리지 않고 슬라이스를 고친다([07의 대비책](07_decisions.md#m3-재미-검증-실패-시-대비책)).

알려진 한계:

- 수호체의 돌진을 기둥으로 유도해 부딪히게 하는 싸움은 사람이 해 보지 않았다. 자동 점검은 약점 노출 시 피해 2배만 확인한다.
- 수호체와 졸개의 수치(체력 1,500, 돌진 35, 포격 25)는 전부 첫 값이다.
- 길찾기 메시는 골짜기의 고정 지형만 포함한다. 복원 뒤 골짜기에 지은 건물은 반영되지 않지만, 그때는 적이 없다.
- 클라이언트 쪽에서 수호체의 포격 표시와 약점 노출이 제대로 보이는지는 여러 프로세스로 확인하지 않았다(이벤트와 플래그는 보낸다).
- 맵은 400×460m 회색 상자다. 소유자가 말한 "훨씬 넓고 탐험할 맛이 있는" 본 맵은 M5의 일이다.

**통과 기준**

- [x] 8인 접속 상태에서 호스트가 업로드 예산을 지킨다 — 자동 조작 클라이언트로 측정
- [x] 누가 어떤 식으로 나가도 호스트 월드가 손상되지 않는다 — 강제 종료 포함
- [x] 호스트가 사라지면 클라이언트가 멈추지 않고 빠져나온다 — `tools/drop_test.sh`, 11초
- [ ] 서로 다른 네트워크의 4명이 Steam 초대만으로 접속한다 — Steam 연동 전
- [ ] 4인 1시간 플레이에서 진행 불가 버그가 없다 — 사람이 해야 한다

**Steam 연동을 시작하지 못한 이유와 필요한 것**

1. GodotSteam의 소스와 배포가 Codeberg로 옮겨 갔고, 이 개발 환경에서는 그 주소에 접근할 수 없다. 현재 API를 확인하지 못한 채 코드를 쓰지 않았다.
2. 실제 동작 확인에는 Steamworks 앱 ID(등록비 필요)와 Steam이 실행 중인 PC가 있어야 한다. 이 환경에는 둘 다 없다.

준비된 것: 전송 종류를 아는 코드는 `core/net.gd`의 `host()`와 `join()` 두 함수뿐이라, Steam용 MultiplayerPeer를 만들어 넣는 분기만 추가하면 나머지(접속 절차, 동기화, 저장)는 그대로 쓴다. 플레이어 키를 접속 이름에서 Steam ID로 바꾸는 자리도 한 곳(`World._player_key`)이다.

그 전까지 친구와 하려면: 한 명이 "호스트"를 누르고 공유기에서 24565/UDP를 열거나, 같은 가상 LAN 도구를 쓴 뒤 다른 사람들이 호스트의 주소로 "참가"한다.
