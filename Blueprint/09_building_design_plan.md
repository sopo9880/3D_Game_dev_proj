# 09. 건축 사용성과 디자인 계획

건축 시스템의 조작 경험과 아트 방향을 모은 문서다. 처음에는 M2 구현 전에 쓴 보완 제안이었고([PR #1](https://github.com/sopo9880/3D_Game_dev_proj/pull/1)), v0.3.1에서 실제 구현과 대조해 항목마다 상태를 붙였다.

**상태 읽는 법**

| 표시 | 뜻 |
| --- | --- |
| 확정 | 구현되어 있고 테스트가 있다. 규칙의 원문은 [02](02_systems.md)다 |
| 채택 | 하기로 했다. 시점이 적혀 있다 |
| 후보 | 아직 정하지 않았다. 구현 요구사항이 아니다 |

이 문서와 01~08이 다르면 01~08이 맞다.

## 1. 목표

- 집·정원·공장을 **하나의 건축 모드**로 짓는다.
- 정확히 맞아야 하는 건물과 설비는 격자로, 꾸미는 장식은 자유 배치로 다룬다.
- 작은 작업장 → 집과 농장 → 다층 공장으로 자연스럽게 커진다. 규모를 강제하지 않는다(D-001).
- 설치 전에 결과를 예측할 수 있고, 실수해도 손해 없이 고칠 수 있다.
- 파쿠르와 전투가 같은 공간에서 일어나므로, 지은 것 위를 실제로 걷고 오를 수 있어야 한다.

| 키 | 동작 | 비고 |

## 3. 미리보기 — 확정

- 조준한 자리에 반투명 모형이 뜬다. **초록 = 설치 가능, 빨강 = 불가**.
- 불가일 때는 이유가 글로 나온다: 자리가 차 있음, 받침이 없음, 재료 부족, 권한 없음, 건축할 수 없는 땅, 광맥 위에만 설치 등.
- 비용과 현재 소지 수량이 함께 나온다(예: 철 주괴 38/10).
- **설비의 포트가 화살표로 보인다**: 입력은 파랑(안쪽을 가리킴), 출력은 주황(바깥쪽), 분배/합류기의 겸용 포트는 보라. 지어진 설비에도 같은 표시가 남는다. 제안서 5장에서 채택했다.
- 클라이언트의 미리보기는 호스트와 같은 규칙으로 계산하지만 판정은 호스트가 한다. 거절되면 이유가 뜨고 소지품은 변하지 않는다.

## 4. 조각과 규칙 — 확정

원문은 [02의 건축 장](02_systems.md#1-건축). 여기서는 제안서와 달라진 점만 적는다.

| 제안서의 표현 | 실제 |
| --- | --- |
| 바닥 4×1×4, 벽 4×4×1 | 바닥은 칸의 **밑면**(4×4칸), 벽은 칸의 **모서리**(4칸 폭 × 4칸 높이)에 놓이는 두께 0.2m 조각이다. 칸을 차지하지 않아 건물 안에 설비를 놓을 수 있다 (D-045) |
| 벨트는 직선 구간 | 두 점을 찍으면 **ㄱ자**로 깔리고, 끝이 포트 앞이면 포트에 곧게 이어지는 쪽으로 꺾인다 |
| 지붕은 별도 조각 | 지금은 바닥과 같은 판이다(건축 목록에 있음). 경사지붕은 5장의 후보 |
| 장식은 충돌 검사 | 다른 장식과 30cm 안에는 놓을 수 없다. 설비·벽과의 겹침 검사는 하지 않는다 |

## 5. 건축 가능 구역 — 확정 (제안서 10-2에 대한 답)

제안서가 물었던 "경사진 지면에서 바닥을 어떻게 놓을지"는 이렇게 정했다.

- 건축은 **건축 구역** 안에서만 된다. 구역은 높이가 정해진 **평평한 단**이다.
- 구역마다 지면 높이가 있고, 그 높이가 그 구역의 "1층"이다. 3m 높은 단 위에서는 바닥·벽·설비가 3m에서 시작하고 2층은 7m다.
- 구역 밖(경사지, 길, 전투 구역)에는 아무것도 지을 수 없다. 미리보기가 "건축할 수 없는 땅"이라고 알려 준다.
- 구역의 경계는 화면에 표시한다(지금은 노란 띠).
- 구역은 월드 상태의 일부다. **구역을 복원하면 그곳의 건축 구역이 열리는** 흐름(02의 복원 보상)을 M3에서 이것으로 구현한다.

이 방식을 고른 이유: 지형 변형이 없다는 원칙(01)과 맞고, 격자가 항상 수평이라 벨트·포트·받침 규칙이 그대로 통한다. 대가는 맵을 만들 때 건축할 곳을 단으로 깎아 두어야 한다는 것이다(D-050).

## 8. 협동·저장·성능

제안서 8장의 요구는 전부 지금 구조로 충족된다.

| 요구 | 어떻게 |
| --- | --- |
| 호스트가 검증하고 전원에게 반영 | 요청 → 호스트 검증 → 틱이 찍힌 이벤트 ([04](04_architecture.md)) |
| 차감과 설치가 어긋나지 않는다 | 비용 차감과 설치가 **한 이벤트** 안에서 일어난다. 소지품이 시뮬레이션 상태의 일부라 해시 비교가 불일치를 잡는다 (D-044) |
| 설치자 기록, 역할 3종 유지 | 구조물마다 설치자를 저장. 방문자의 설치·철거는 호스트가 거절 |
| 재시작 후 구조물·설비·소지품 보존 | 저장 점검이 해시로 확인 |
| 먼 공장을 단순하게 그려도 계산은 같다 | 시뮬레이션은 거리와 무관 (D-010) |

아직 확인하지 못한 것: 설비 500개와 큰 다층 건물에서의 **실제 프레임**. 조각마다 노드와 충돌체가 하나씩이라 건물이 커지면 느려질 수 있다(Q-04).

## 9. 아트 방향 — 후보

스타일라이즈드 로우폴리는 확정이고([01](01_vision.md)), 아래는 에셋을 만들 때의 지침 후보다. 지금 게임의 모든 모형은 임시 상자다.

- **주거**: 따뜻하고 부드러운 실루엣, 자연과 어울리는 형태.
- **공장**: 규격이 정확하고 방향과 동작이 읽히는 실루엣, 절제된 발광.
- **공통**: 둘을 섞어 지어도 어색하지 않게 비례·조명 반응·색 톤을 맞춘다.
- **인테리어**: 적은 부품으로 아늑해 보이도록 형태를 분명하게.
- **전투 시인성**: 적·엄폐물·사격 효과와 헷갈리지 않게 장식의 복잡도를 관리한다.
- 모든 에셋은 1m 격자, 4m 모듈, 지금의 충돌 형상에 맞춘다.

재질 팔레트, 낮밤과 날씨, 직접 제작·구매·외주 비율은 정하지 않았다(Q-06, Q-10).
