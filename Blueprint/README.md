# Edenfall Blueprint v0.2

이 폴더는 Edenfall의 **단일 기준 문서(single source of truth)** 다. 초기 기획(v0.1)을 검토해 모순을 없애고, 결정되지 않았던 부분을 결정하고, 1인 개발로 실제 만들 수 있는 크기로 다시 잘랐다.

코드와 이 문서가 다르면 둘 중 하나가 버그다. 설계를 바꿀 때는 코드보다 먼저 여기를 고치고 [07_decisions.md](07_decisions.md)에 한 줄 남긴다.

## v0.1에서 바뀐 것

방향(힐링 + FPS + 공장 + 4인 협동, 공장 B안, PvP는 아레나 전용)은 그대로다. 바뀐 것은 범위, 순서, 그리고 v0.1이 비워 둔 기술 결정이다.

| # | v0.1 | v0.2 | 이유 |
| --- | --- | --- | --- |
| 1 | 첫 버전에 PvP 1v1 포함 | **슬라이스에서 제외**, 4인 협동 이후(M5)로 이동 | 핵심 루프 검증과 무관하고, 경기 상태·표준 장비·아레나가 통째로 추가 작업이다 |
| 2 | 첫 버전에 "공동·개인 저장" 전체 포함 | 슬라이스는 **월드 1개 저장/불러오기 + 백업**만 | 저장은 처음부터 버전 관리하되 기능은 최소로 |
| 3 | 개발 순서: FPS+멀티 → 공장 → 힐링 | **M0에서 네트워크 뼈대와 공장 시뮬레이션 코어를 함께 검증** | 가장 위험한 두 가지(멀티 구조, 공장 성능)를 가장 먼저 확인한다 |
| 4 | 플레이어 동기화: "입력 처리·서버 판정" | **이동은 클라이언트 권한 + 호스트 검증, 명중은 사수 판정 + 호스트 검증** | 친구끼리 하는 협동 PvE에 서버 권한 이동과 예측·롤백은 비용 대비 이득이 없다. 조작감이 우선이다 |
| 5 | MultiplayerSpawner/Synchronizer를 전반에 활용 | **플레이어·적·투사체에만** 사용. 구조물과 공장은 명령/이벤트 + 스냅샷으로 자체 복제 | 구조물 수천 개를 노드별로 동기화하면 무너진다 |
| 6 | 멀리 있는 공장은 단순화 계산 | **시뮬레이션은 거리와 무관하게 동일, 렌더링만 단순화** | 가까이 있을 때와 멀리 있을 때 생산량이 달라지면 버그와 악용의 원인이 된다 |
| 7 | 컨베이어 "수량 기반" (구체 모델 없음) | **벨트 라인 단위 슬롯 큐, 10Hz 정수 틱** 으로 확정 | 물건이 실제로 줄지어 가는 모습과 성능을 둘 다 얻는다 |
| 8 | 기계와 벨트 연결 방식 미정 | **포트 직결 방식**(집게팔 없음). 분배/합류기 추가 | 3D 1인칭에서 다루기 쉽고 엔티티 수가 절반으로 준다. v0.1의 "채굴기 1 → 제련기 2" 예시는 분배기 없이는 불가능하다 |
| 9 | 권한: 구조물별 소유자/건설/이용 | 출시 전까지는 **월드 단위 역할 3종**. 구조물에는 설치자만 기록 | 4인 친구 협동에 구조물별 권한 UI는 과하다. 데이터는 남겨 두므로 나중에 확장 가능 |
| 10 | 개인 데이터 저장 위치 불명확 | **캐릭터 진행은 호스트 월드 세이브 안에**, 장식·칭호만 계정 단위 | 월드 간 아이템 복사를 막고, 접속 종료 시 저장 책임을 한곳에 둔다 |
| 11 | 월드: 구역 분할·거리 기반 로딩 | 슬라이스는 **스트리밍 없는 단일 맵**. 구조물 좌표만 처음부터 청크 단위로 관리 | 맵 스트리밍은 맵이 커진 뒤에 필요하다. 데이터 구조만 미리 대비한다 |
| 12 | 공해·소음 "나중에" | **명시적으로 범위 밖** | 긍정 보상 구조와 충돌하고 검증할 가치가 낮다 |
| 13 | 되돌리기 "제공" | **본인이 방금 한 설치/철거만**, 최근 20개 | 공유 월드에서 전역 되돌리기는 정의할 수 없다 |
| 14 | 사망 규칙 없음 | **소지품 유지, 안전 지점에서 부활** | 힐링 게임의 톤과 "전투를 강제하지 않는다"는 원칙 |
| 15 | 성능 목표 없음 | **수치 예산 명시** ([04](04_architecture.md#성능-예산)) | 측정할 수 없으면 지킬 수 없다 |
| 16 | 테스트 언급 없음 | **시뮬레이션 코어는 헤드리스 단위 테스트 필수** | 공장 로직은 화면 없이 검증할 수 있어야 저장·멀티 버그를 잡는다 |

## 용어

| 용어 | 뜻 |
| --- | --- |
| 호스트 | 월드를 연 플레이어. 게임 상태의 최종 권한을 가진다 |
| 구조물 | 건축 모드로 설치한 모든 것(바닥, 기계, 가구, 식물 화분) |
| 설비 | 구조물 중 공장 시뮬레이션에 참여하는 것(채굴기, 벨트 등) |
| 틱 | 공장 시뮬레이션의 한 걸음. 0.1초 |
| 구역 | 오염/복원 상태를 갖는 월드의 한 영역 |
| 슬라이스 | 버티컬 슬라이스. 30분 분량의 첫 완성형 플레이 |
